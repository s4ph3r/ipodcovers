# ipodcovers — Конвертер обложек для цветных iPod Classic с прошивкой RockBox

Консольная программа на Python для рекурсивной обработки всех изображений в указанной директории. Программа предназначена для подготовки обложек (artwork) для **цветных iPod Classic** — приводит все найденные изображения к формату **JPEG Baseline** с ограничением максимального размера **600 пикселей** на большую сторону, создаёт файлы с именами `cover.jpg`, `cover1.jpg`, `cover2.jpg` и т.д., а оригиналы переименовывает в `*.bak`.

> **Примечание:** iPod Classic использует специфический формат обложек — JPEG Baseline не более 600px на большую сторону. Эта программа автоматически конвертирует любые изображения (PNG, BMP, TIFF, Progressive JPEG и др.) в требуемый формат для корректного отображения в библиотеке iTunes.

## Возможности

- 📁 **Рекурсивный обход** — обрабатывает все поддиректории независимо от глубины вложенности
- 🖼️ **Поддержка форматов** — JPEG, JPG, PNG, BMP, TIFF, TIF, GIF, WEBP, ICO, PCX, PGM, PPM, PNM, SGI, TGA
- 🔄 **Конвертация в JPEG Baseline** — все изображения сохраняются как JPEG Baseline (не Progressive)
- 📐 **Умный ресайз** — если изображение больше 600px на любую сторону, оно масштабируется пропорционально, чтобы большая сторона стала ровно 600px
- 📝 **Инкрементное именование** — первый файл получает имя `cover.jpg`, последующие — `cover1.jpg`, `cover2.jpg` и т.д. (каждый счётчик начинается заново в каждой директории)
- 💾 **Резервное копирование** — оригиналы переименовываются с расширением `.bak`
- 🎨 **Цветной вывод** — зелёный (OK), тёмно-жёлтый (обработан), стандартный (не изображение), красный (ошибка)
- 🔁 **Безопасность повторных запусков** — файлы `cover*.jpg` и `.bak` автоматически пропускаются при повторном запуске
- 🌍 **Поддержка кириллицы** — корректно работает с русскими названиями файлов и папок
- ⚡ **Автоматическая установка зависимостей** — при отсутствии библиотек предлагает установить их через pip

## Установка

### Требования

- Python 3.6 или выше
- Библиотека Pillow (обработается автоматически)

### Запуск

Программа является самодостаточным скриптом без установки. Просто сделайте его исполняемым и запускайте:

```bash
chmod +x ipodcovers
./ipodcovers /путь/к/директории
```

Или через Python:

```bash
python3 /home/user/ipodcovers /путь/к/директории
```

## Использование

### Базовый синтаксис

```bash
./ipodcovers <путь_к_директории> [опции]
```

### Примеры

```bash
# Обработка всех изображений в директории
./ipodcovers /home/user/photos

# Обработка с резервным режимом (только показ действий)
./ipodcovers ~/images --dry-run

# Вывод справки
./ipodcovers --help
```

### Опции

| Опция | Описание |
|-------|----------|
| `--dry-run`, `-n` | Показать что будет сделано, не изменяя файлы |
| `--help`, `-h` | Вывести справку и завершить работу |

## Как работает программа

### Алгоритм обработки

1. **Сканирование** — программа рекурсивно обходит все поддиректории и собирает список всех файлов с расширениями изображений
2. **Фильтрация** — файлы с именами `cover*.jpg` и `.bak` пропускаются (защита от перезаписи при повторных запусках)
3. **Определение типа файла**:
   - Если файл не является изображением → выводится сообщение стандартным цветом
   - Если файл уже JPEG Baseline и все стороны ≤ 600px → помечается как "полностью OK" (зелёный цвет)
   - Если требуется обработка → выполняется ресайз и/или конвертация (тёмно-жёлтый цвет)
4. **Создание cover-файлов**:
   - Для каждого нового изображения определяется свободное имя: `cover.jpg`, `cover1.jpg`, `cover2.jpg`...
   - Если текущий файл уже имеет имя `cover*.jpg` — он используется как цель (перезаписывается на месте)
5. **Резервное копирование** — оригинал переименовывается в `*.bak`
6. **Удаление оригинала** — если новый файл создан с другим именем, оригинал удаляется
7. **Финальный запрос** — в конце программы спрашивает пользователя, нужно ли удалить все `.bak` файлы

### Правила именования

В каждой директории создаётся уникальный набор файлов:

| Ситуация | Имя файла |
|----------|-----------|
| Первое изображение в папке | `cover.jpg` |
| Второе изображение в папке | `cover1.jpg` |
| Третье изображение в папке | `cover2.jpg` |
| И так далее... |

**Важно:** Каждый счётчик начинается заново в каждой отдельной директории. Если в `/home/user/photos/2024/` есть два изображения, они получат имена `cover.jpg` и `cover1.jpg`. В `/home/user/photos/2025/` тоже будут `cover.jpg` и `cover1.jpg`.

### Правила обработки изображений

#### 1. Полностью соответствующие условиям
- Формат: JPEG Baseline (`progressive=False`)
- Размер: все стороны ≤ 600 пикселей
- **Действие:** создаётся `.bak` копия, файл копируется как `cover*.jpg`, оригинал удаляется (если имя отличается)

#### 2. Требующие обработки
- Не JPEG Baseline (например, PNG, BMP, JPEG Progressive)
- Или размер больше 600px на любую сторону
- **Действие:** создаётся `.bak` копия, файл ресайзится (пропорционально, большая сторона = 600px), конвертируется в JPEG Baseline, сохраняется как `cover*.jpg`, оригинал удаляется

#### 3. Не изображения
- Файлы с другими расширениями или неопознанные форматы
- **Действие:** пропускаются без изменений, выводятся стандартным цветом

### Повторные запуски

При повторном запуске в той же директории:

- Все файлы `cover*.jpg`, `cover1.jpg` и т.д. автоматически пропускаются
- Если файл уже имеет нужное имя (JPEG Baseline ≤ 600px) → выводится зелёным сообщением "уже cover*.jpg, полностью соответствует условиям"
- Если файл имеет имя `cover*.jpg` но требует обработки (например, разрешение больше 600px) → он перезаписывается на месте

## Цветовая схема вывода

| Цвет | Значение | Пример сообщения |
|------|----------|------------------|
| 🟢 **Зелёный** | Полностью соответствует условиям | `Файл пропущен (полностью соответствует условия...` |
| 🟡 **Тёмно-жёлтый** | Требует обработки | `Файл обработан (размер изменён: 800x600 -> 600x450, конвертирован из png в JPEG Baseline)` |
| ⚪ **Стандартный** | Не изображение | `Файл пропущен (не изображение): /path/to/file.mp3` |
| 🔴 **Красный** | Ошибка | `Ошибка открытия /path/to/file.jpg: ...` |

## Технические детали

### Зависимости

- **Pillow** — основная библиотека для работы с изображениями (открывает, ресайзит, сохраняет)
- **Стандартная библиотека Python** — `os`, `shutil`, `pathlib`, `subprocess`, `argparse`

### Формат JPEG Baseline

JPEG Baseline — это базовый формат JPEG, который:
- Поддерживается всеми устройствами и браузерами без ограничений
- Не использует прогрессивную загрузку (в отличие от JPEG Progressive)
- Обеспечивает максимальную совместимость для iPod и других портативных устройств

Программа проверяет флаг `progressive` в метаданных изображения. Если он установлен в `True`, файл перезаписывается как JPEG Baseline.

### Права доступа

При создании новых файлов (`cover*.jpg`) программа копирует права доступа (`chmod`) от оригинального файла, чтобы сохранить их неизменными.

## Известные ограничения

- Программа не удаляет файлы с расширениями, не входящими в список поддерживаемых
- При обработке файлов с одинаковыми именами в разных директориях каждая получает свои `cover*.jpg` (счётчик сбрасывается)
- Если файл уже имеет имя `cover*.jpg` и требует обработки, он перезаписывается на месте без создания нового файла

## Использование с iTunes и iPod Classic

### Подготовка обложек для iPod Classic

iPod Classic отображает обложки альбомов (artwork) из файлов `cover.jpg`, расположенных рядом с музыкальными файлами в папках альбома. Для корректной работы требуется:

1. **Формат:** JPEG Baseline (не Progressive, не PNG, не TIFF)
2. **Размер:** максимальная сторона не более 600 пикселей
3. **Имя файла:** ровно `cover.jpg` (в каждой папке с музыкой альбома)

### Типичный рабочий процесс

```bash
# 1. Поместите все обложки альбомов в одну директорию
#    Структура:
#    /home/user/artwork/
#      album1/photo1.png
#      album1/photo2.jpg
#      album2/cover.png
#      ...

# 2. Запустите конвертер
./ipodcovers /home/user/artwork

# 3. Скопируйте готовые cover.jpg в папки с музыкой
#    Каждая папка альбома должна содержать свой cover.jpg
```

### Важные замечания для iPod Classic

- Каждый альбом должен иметь **свой** `cover.jpg` в своей папке
- Если в альбоме несколько треков без обложек — программа создаст `cover.jpg`, `cover1.jpg`, `cover2.jpg` и т.д.
- iTunes автоматически считывает только файл с именем `cover.jpg` для каждого альбома
- Размер 600px — максимальный размер, который iPod Classic корректно отображает в интерфейсе

### Почему JPEG Baseline?

iPod Classic не поддерживает JPEG Progressive или другие продвинутые форматы для обложек. JPEG Baseline — это базовый, наиболее совместимый формат, который гарантированно работает на всех версиях прошивки iPod Classic RockBox.
